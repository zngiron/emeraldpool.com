What this is

A base theme and twelve blocks, configured for one brand.

Nothing here is a page builder, and nothing is for sale. Spa models are a custom post type — a marketing catalogue, not a shop — so there is no WooCommerce, no cart, and no checkout to maintain.

  • zngiron-baseThe theme. Every design decision is a theme.json preset; every page section is a pattern.
  • zngiron-blocksThe plugin. Twelve server-rendered blocks, the spa post type, and the schema output.
  • config/brand.jsonThe brand. Name, post types, taxonomies, meta fields and store locations — one file.
  • Editors work in GutenbergThe blocks sit in an inserter category named for the brand. No shortcodes, no custom admin screens to learn.
  • Deployment needs no NodeThe compiled blocks are committed. Node is only needed to change the block source.
  • Rebrandable on purposeEmerald Pool is the first brand on the system, not the system itself.

Configured, not coded

Adding a specification is editing one file.

The spa post type, its two taxonomies and its eleven meta fields are declared in config/brand.json. A field flagged specs becomes a row in the Specs Table; a field flagged compare becomes a row in the Compare Table. Neither block is edited to add one.

Post type

Taxonomies

Setup

Four commands, and nothing installed on the machine.

# once
cp .env.example .env

# start wordpress + mariadb
make up

# install, activate, permalinks
make install

# images, spas, pages, posts
make seed

Everything runs in containers, under Docker or OrbStack. No PHP, no MySQL and no Node are installed on the host. The first run pulls the images; after that it is seconds.
